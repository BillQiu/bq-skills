# 评分规则

## 目标

从当天论文中选出最值得读的 5 篇，不是最热门的 5 篇。

## 一、硬过滤

直接剔除以下论文：

- 纯理论数学证明，且无明确工程、方法或系统落地潜力
- 非计算机科学领域的跨学科应用工作
- 只有应用包装，没有通用方法增量
- 与用户关注方向弱相关，且缺乏明显通用价值

可保留例外：

- 跨学科场景，但贡献点是通用架构、训练方法、推理方法、索引机制或系统优化
- 不在主偏好里，但当天异常热门且对通用 LLM/agent 系统可能有明显外溢价值

## 二、主题优先级

### 第一优先

- agent
- 自动代码生成
- Bug 修复
- 系统配置优化

### 第二优先

- LLM agent infrastructure
- tool use
- planning
- workflow orchestration
- code reasoning

### 第三优先

- 高质量合成数据生成

### 第四优先

- RAG 索引优化

### 第五优先

- 其他当天非常热门且对通用智能体/LLM 系统有外溢价值的论文

## 三、辅助判断维度

主题优先级之外，再看以下信号：

- 是否有明确方法增量，而不只是任务包装
- 是否有系统实现、工具链、训练或推理机制改进
- 是否有明显工程落地潜力
- 是否有开源潜力或复现价值
- 是否可能服务后续 `bq-paper` 深读

以下信号应降低评分：

- 纯 benchmark 组织，方法贡献弱
- 只是把现有方法换一个领域应用
- 主要靠规模堆料，机制解释弱
- 明显营销式标题，但摘要中方法细节空洞

## 四、热度修正

若论文命中 `Hugging Face Papers`，可加热度分。

原则：

- 热度只能修正排序，不能推翻主题相关性
- 强相关但不热的论文，优先于弱相关但很热的论文
- 若热点论文仅具一般相关性，更适合进入“补充推荐”

## 五、多样性控制

Top 5 里同类方向最多 2 篇。

同类示例：

- 连续多个 code agent
- 连续多个纯 RAG 检索
- 连续多个 synthetic data pipeline

若当天某一方向过热，也要尽量保留其他高质量子方向的曝光。

## 六、输出决策口径

每篇入选论文至少要能回答下面四个问题中的三个：

1. 它和用户关注主题的关系是什么？
2. 它的方法增量是什么？
3. 它有没有工程或开源潜力？
4. 它值不值得交给 `bq-paper` 深读？

如果四个问题都回答得很虚，这篇论文不该进入 Top 5。
