# 数据源策略

## 目标

为“每天固定输出 Top 5”提供稳定、低噪声、可解释的数据源组合。

## 数据源分层

### 1. 主源：arXiv

用途：

- 当天新增论文主池
- 作为论文发现的第一入口

原因：

- CS 与 LLM 相关论文覆盖最全
- 更新快，适合日报
- 标题、摘要、分类等元数据完整

策略：

- 默认优先使用 `cs.*`
- 允许少量补充 `stat.ML`
- 遇到明显不属于目标方向的论文，靠分类与摘要二次过滤

### 2. 热度修正源：Hugging Face Papers

用途：

- 给主池增加“社区关注度”信号
- 帮助发现当天高讨论度论文

原因：

- 适合作为热点层，而不是全量来源
- 能修正“相关但不一定最值得今天读”的排序问题

策略：

- 只作为加分项，不作为唯一入选条件
- 若热点论文与用户关注方向弱相关，只能进入补充推荐，不应轻易挤掉主线论文

### 3. 预留补充源：OpenReview

用途：

- 补会议信号
- 捕获还未完全沉到 arXiv 热点中的前沿投稿

原因：

- 前沿性强
- 但公开访问与页面结构稳定性较弱，不适合作为第一版核心依赖

策略：

- 第一版不强依赖
- 后续若用户更关注会议投稿，再接入

### 4. 元数据增强源：OpenAlex

用途：

- 补主题、开放获取、引用等元数据

原因：

- 更适合做增强，不适合直接做每日主发现
- 通用搜索噪声较高，需要已有候选池后再查

策略：

- 第一版仅作为可选增强
- 不作为第一版必要依赖

## 明确不作为第一版主依赖的来源

- `Semantic Scholar`
  匿名接口限流明显，适合增强，不适合日报主流程
- `DBLP`
  更偏书目索引，对“当天新论文发现”帮助有限
- 各类社交媒体榜单
  热度强，但噪声和波动都高，不适合作为主规则

## 推荐组合

第一版推荐组合：

- 主池：`arXiv`
- 热度修正：`Hugging Face Papers`

扩展版可加入：

- `OpenReview`
- `OpenAlex`
