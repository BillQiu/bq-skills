# wiki-mark · 会话中途给 wiki 打标记

把「这一刻值得入库」的信号落盘到 wiki 的标记队列，几秒完成，然后回到原话题。会话本身会被 capture.py 定时自动转写，标记只负责让它在 160+ 条的 pending 队列里不被淹没。

## 宪法边界（已核验，打标时无需再读 wiki 宪法）

- 只追加写一个文件：`/Users/billqiu/workspace/wiki/state/marks.md`
- 不碰 `raw/`、知识层 `wiki/`、`state/pending.md`；不跑 capture.py；不 git commit
- 标记 ≠ 审批。写知识层仍须在 wiki 项目里走 `/wiki:ingest` 审批环

## 执行步骤

1. **推导三元组**（禁止问用户）：
   - 时间：`date "+%Y-%m-%d %H:%M"`
   - 项目、会话：从系统提示的 scratchpad 路径取——`…/claude-501/<项目段>/<会话UUID>/scratchpad`；项目记项目段去掉 `-private-tmp-` / `-Users-billqiu-` 等前缀后的短名，会话记 UUID 前 8 位。取不到时回退：`ls -t ~/.claude/projects/<项目目录>/*.jsonl | head -1`，文件名即会话 UUID。
2. **摘锚文本**：从刚才的对话里**逐字**摘 1–2 句独特原话（每句 ≤50 字，独特到将来能在转写里 grep 定位）。禁止转述改写；禁止编造轮次号——`#Txxx` 由入库时对真实转写解析。
3. **记想法**：用户 `/wiki-mark` 后面跟的文字**原样**记录，标「用户原话」。用户没给想法时：拟一句 ≤30 字候选，当场请用户确认或改写，落盘标「AI 拟·用户已确认」。
4. **追加条目**：文件不存在则先建（含下方文件头）；已存在则**只在末尾追加**，不重排、不清理、不改动既有条目。
5. 一句话告知已标记，**回到被打断的原话题**。

## marks.md 格式

文件头（仅新建文件时写一次）：

```markdown
# 标记队列（/wiki-mark 追加；wiki 项目 /wiki:ingest 消费后勾销）

> 本文件不是知识层。条目是未经审批的入库线索；写知识层仍走审批环。
```

条目模板（严格照此追加，字段名不增不减）：

```markdown
- [ ] 2026-07-24 15:02 · billq-nN3cI8 · c6f8371d
  锚："乱序不是毛病，乱序就是他的处境"／"第二句可选，两句用／分隔"
  想法：意识流的适用场景判断可以复用，想收进 concept（用户原话）
  类型提示：concept
```

类型提示可选值：`concept` / `opinion 候选` / `entity` / `analysis` / `无`。用户没指明时按对话内容判断，拿不准填 `无`。

## 常见错误

- ❌ 借标记之机建 concept 页、写任何 `wiki/` 或 `raw/` 文件——那是绕过审批环
- ❌ 把 AI 的转述标成「用户原话」——出处污染，毁掉 opinion 管线的原料
- ❌ 用 Write 重写整个 marks.md 覆盖历史条目——必须追加式写入
- ❌ 为打一次标去通读 wiki 宪法或侦察仓库——本 skill 已给出全部边界，直接执行
- ❌ 当场跑 capture.py 想立即生成转写——活跃会话捕不到，交给定时任务
